## Goal

## Deliverables

## End-to-end check

### Migrations / Production is forward only

**R-0577** Rolling back after new data has been written can fail or lose that data, so production moves forward only. `down.sql` is still proven for every migration, because `revert` and development depend on it.

- **R-0578** **`mode development` must name the database,** as in `mgr mode development --confirm app_staging`, so a command aimed at the wrong URL can't remove the protection.
- **R-0579** **Every database is production until marked otherwise.** The mode is stored in `_morm`, not in an environment variable, so a wrong setting on a host can't turn it off, and a backup restores with it. Forgetting to mark a database leaves it safe.
- **R-0580** `morm-admin mgr mode development` marks a local or staging database, and `mode` shows the current value. Every change goes in `_morm.history`.
- **R-0581** **On a production database,** `rollback` and `rehearse` exit with code `2`. To rehearse on a clone of production, mark the clone first.
- **R-0582** **`morm-admin mgr revert ID`** is the way to undo in production. It creates a new forward migration from that migration's down, runs the full proof on scratch, and needs the same decisions, such as `down_fill`. Retired columns and tables come back with their data, and the chain stays linear, so every database has the same history.
- **R-0584** **Emergency override:** `rollback --production --reason "..."` works but is logged to `_morm.history`, and it still needs `--accept-data-loss` where that applies.

### Migrations / Commands

- **R-0616** `rehearse`: pending up → down → up on a clone or restored backup, with **real data**. The recommended last gate.
- **R-0620** `squash --to ID`: replaces the chain up to `ID` with one baseline generated by replaying it. A database that has applied all of them just continues, and one partway through is refused until it catches up. Run it only when every database has passed `ID`. It refuses while retired objects from those migrations haven't been purged, because their rollback path would be gone.
